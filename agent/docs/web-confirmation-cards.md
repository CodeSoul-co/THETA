# Agent 对话卡片：交互设计与专项验收

日期：2026-09-10，23:25 更新。复用现有前端，仅调整 Agent 对话模式的确认卡及相关布局。

## 出现方式

- 只有核心产生真实待授权操作时才出现卡片。普通讨论、数据理解和补充问题不伪造授权卡。
- 待确认卡固定在输入框上方，与输入框等宽；消息流仅保留一条“在下方确认”的定位记录。滚动历史时仍能操作，不使用遮罩或模态弹窗。
- 训练卡用两列标签与值展示数据、模型、正文/时间列、设备、运行上限、主题数与迭代上限；embedding 和外部请求范围仍可直接阅读。完整说明按需展开；结果卡先展示执行范围，任务 ID 缩略显示，原始 ID 保留在详情中。
- 长说明仅在卡片正文内部滚动，标题和操作区固定。窄屏改为单列，操作按钮至少 44 px 高。浅色和深色使用各自的文本、边框和按钮颜色。
- 以卡片 ID 和内容 hash 判定当前版本。普通消息、工具事件和时间戳更新不会让卡片失效；方案变化后，旧卡只能查看详情。

## 决定与反馈

| 场景 | 用户操作 | 结果 |
| --- | --- | --- |
| 接受原方案 | 确认执行 | 仅授权当前卡片；提交中禁用按钮，服务端防重复消费 |
| 暂时不做 | 拒绝本次 | 无须填写理由，拒绝后继续对话，不自动重弹同一操作 |
| 有修改意见 | 点击修改方案，填写反馈并提交修改 | 原授权被拒绝；Agent 按反馈准备新卡，仍需再次确认 |
| 填写意见后误点确认 | 主按钮切换为提交修改 | 编辑期间不显示执行原方案入口；取消修改后才恢复确认 |
| 刷新或切换对话 | 恢复对话 | 服务端恢复卡片和决定；同一标签页恢复未提交反馈草稿 |
| 网络失败 | 查看错误后重试 | 保留反馈和卡片；显示可理解错误，不提前显示成功 |
| 已处理、被替换或过期 | 查看历史卡 | 明确区分已确认、已拒绝、已提交修改、已失效、已过期；不可再次执行 |
| 操作执行失败 | 查看错误 | 不伪造成功；核对服务端状态，有效待确认卡可重试，已消费操作不得重复授权 |

历史卡片保存原始说明、版本、决定和反馈，不依赖浏览器本地历史。授权状态与训练是否完成分别展示，“已确认”不等于“训练成功”。

## 首轮浏览器验收（原内联布局）

使用原有36行合成CSV以及已有对话 `chat-37b91145-47e3-43fa-9a74-0cf24238b078`。

1. 生成2主题、8次迭代的训练卡；直接拒绝，不填写理由。原卡显示已拒绝，Agent 说明未执行，并保持不再弹卡。
2. 用户主动重新申请，生成新卡。在卡内输入多行反馈“改为5次迭代”；确认按钮禁用，提交修改可用。
3. 刷新页面并恢复对话，未提交反馈仍在。提交修改后旧卡显示已提交修改，新卡为2主题、5次迭代，反馈框为空。
4. 重复点击确认新卡，服务端仅出现一个新任务：`job-23f0d6ca59c0ebe9da279a6775fbcc47564868fb8045108d4323ccf3ba559d74`。旧任务保留。
5. 新任务真实完成后自动出现独立结果整理卡；拒绝结果整理不撤销训练，也不生成新报告。
6. 主动重新申请结果卡。停止本地API以模拟服务中断，再提交范围反馈；页面显示连接失败，反馈未丢失，原卡保持待确认。恢复API后原反馈可以直接重试。
7. 重试后产生新的结果卡，确认后报告状态为 complete，网页收到报告链接。6张新卡的服务端终态为：2张已拒绝、2张已提交修改、2张已确认；本轮仅新增1个训练任务。
8. 初次连接失败的模型控件显示明确重试入口，点击后恢复当前模型显示。

## 自动回归

`npm --prefix agent test` 覆盖65项测试。Web专项包含：首次发送、附件、旧卡保护、并发/停止、文件链接、归档，以及新增的拒绝持久化与重复请求、修改反馈校验、未知动作/错误hash、替换与时间稳定、执行错误、过期卡。

核心回归同时检查：普通旁问不消费卡片；“确认，但换个模型”不视为授权；数据/端点变化使原确认无效；请求已有任务时解释当前状态，要求先保存新方案后才申请新实验卡。

`npm --prefix frontend run build` 包含前端TypeScript检查。

此次浏览器专项实测训练卡和结果整理卡。深入解读、训练取消共享相同决定组件和服务端校验，但本轮未对这两类卡单独执行完整计算验收。

## 输入框上方确认卡：本轮真实用户验收

在项目“多模型与论文解读验收”的既有 LDA 对话中执行，使用已有 180 行合成语料。前端为 `http://127.0.0.1:4320/workbench?mode=conversation`；所有操作经页面完成，未通过 CLI 发起训练。

| 场景 | 实测结果 |
|---|---|
| 申请 LDA 训练卡 | 卡片在输入框上方出现，关键信息与按钮全部可见；无重复完整表单 |
| 修改 5 次迭代为 3 次 | 点击修改方案后自动聚焦意见框；提交修改可用，确认执行入口隐藏 |
| 刷新与重新进入对话 | 同版本卡片及修改草稿恢复；新版本不继承旧反馈 |
| 提交修改 | 提交阶段所有决定按钮锁定；旧卡变为“已提交修改”，新卡显示 3 次迭代 |
| 390×844 窄屏 | 单列事实、44 px 操作按钮；拒绝/修改/确认同时可见，模型名称保持单行 |
| 拒绝新训练方案 | 卡片消失，历史显示“已拒绝”，没有启动训练 |
| 再次申请 2 次迭代方案 | 新卡正常出现，与已拒绝卡分开记录 |
| 展开完整长方案 | 卡片正文滚动，标题、按钮不被长参数和路径挤走 |
| Enter 打开修改、取消编辑 | 修改意见被取消后恢复原确认按钮，焦点返回修改按钮 |
| Enter 确认执行 | 显示“正在确认操作”；按钮禁用；随后收为“启动训练 · 已确认” |
| 执行完成与后续授权 | 仅新增一个真实训练任务，约 16.8 秒完成；后续结果整理单独弹卡 |
| 报告卡 | 先显示读取范围和不包含的深入解读；任务 ID 不占整行正文 |
| 深色模式 | 卡片、正文、次要文字及主按钮可读；验收后恢复原浅色设置 |
| 拒绝后续报告 | 训练仍为已完成，不读取或生成新报告；已拒绝状态保留 |
| 已处理卡展开/收起 | 原始方案、反馈和明确结果说明可回看；无第二组决定按钮，无头像/点赞占位 |

服务端四张新卡终态为 **revised、rejected、approved、rejected**；会话没有 pendingConfirmation 或 pendingSynthesis。唯一新增训练任务为 `job-7133080f2d91983bc5afe2da256705927676980f79410ddd05c6f7dd5b4521c0`。此任务仅用于交互验证，不替换多模型分析报告中的正式验收实验。

“已确认”只表示确认决定，执行状态独立显示。简短的确认/默认拒绝消息在相邻决定记录已明确表达时不再重复画气泡，用户实际修改意见仍保留。普通助手回复仍使用原有消息组件。

本轮改动：`ConversationPane.tsx`、`ActionApprovalCard.tsx`、新增独立 `ActionApprovalCard.module.css`，以及原样式中模型名称的单行溢出处理。保留卡片 ID/hash 校验、服务端防重复消费和原授权流程。草稿现在同时绑定会话、卡片及内容版本。

本轮验证：前端 TypeScript 与生产构建通过；桌面与窄屏、浅色与深色均经浏览器实际检查。未改动本轮之外的模型或服务端授权逻辑；网络失败等服务端分支沿用首轮测试记录，不冒充本轮重新实测。
