# 训练状态与进度观察

终端每 3 秒查询当前研究的任务。输入消息或等待对话模型时，状态区仍刷新；不会为查询状态额外调用语言模型。查询失败会保留监控并重试，不会重新提交训练。退出终端后后台训练继续，使用 `./theta --session <会话标识>` 恢复监控。

本地管线的 20%、60% 是阶段标记，不是完成比例。终端展示实际阶段、运行时间、阶段时间、worker 心跳和日志距今时间。日志有明确迭代记录时显示“已报告迭代 n/N”，不表示该迭代已完成，也不推算 ETA。其他算法没有这种日志时，不虚构迭代进度。

心跳 30 秒内更新只表明 worker 仍响应。没有新日志时，显示暂无算法推进证据；超过 30 秒未收到心跳则显示状态不确定。既不把安静视为失败，也不把心跳视为训练质量正常。结束状态仍以计算任务记录为准。

`ComputeJob.telemetry` 是与 CLI 无关的 `theta.job-observation.v1` 结构，包含观察时间、健康信号、阶段时间、日志新鲜度及可验证的迭代。后续 Web 可直接消费。未提供 telemetry 的远程 worker 显示缺少细粒度进度。运行中日志仅提取限定的活动信号，不展示原文或进行结果解读。

本次只修改 `agent/`。本地适配器负责记录时间和独立心跳，并读取已有 worker 日志；没有修改根目录 `src/`、`trainning/`、算法、可视化或训练参数。升级前已启动的任务可以读取日志/心跳，但缺少的开始时间不会补造。新启动任务才会使用新增的独立心跳。

## 验证

- `pnpm --dir agent test`：提示、状态展示和等待模型时的并行观察。
- 在 `agent/` 运行 `.venv/bin/python -m unittest discover -s workers/tests -t .`：心跳/日志区别、迭代、阶段时间、旧任务兼容。
- `agent/.venv/bin/python agent/scripts/test-training-monitor.py`：以 PTY 启动真实 `./theta`，使用隔离的模拟任务验证迭代刷新、心跳过期、查询失败后恢复，以及刷新时保留输入中的 `/help`。此项是终端回归测试，不是模型训练验收，不调用推理或训练。
